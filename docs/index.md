# DevContainer Template

A reusable foundation for building understandable, auditable, and maintainable projects.

This handbook teaches more than how to operate the template. It explains how the pieces fit together and how disciplined development moves from an uncertain idea to maintained software.

## Reading path

1. Begin with [Why this template exists](learn/philosophy.md) and [The project model](project-model.md).
2. Use [Getting started](learn/getting-started.md) to enter the reference development environment.
3. Study the [Foundations](foundations/index.md) to understand the files already provided.
4. Learn the difference between [hard and soft constraints](constraints/index.md).
5. Follow the [development workflow](workflow/index.md) from problem definition through maintenance.
6. [Adapt the template](adaptation.md) only after the project has made its language and product decisions.

## Two sources of truth

The repository contains two related kinds of truth:

- Code and configuration describe what the project does now.
- GitHub issues, pull requests, and history explain why it changed.

Documentation connects those truths without trying to duplicate either one. It explains the stable mental model, boundaries, and operating method.
